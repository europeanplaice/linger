Bring your own S3 bucket

Self-hosting guide — optional & advanced

Do I need this?
No, for most people this is not needed. Your diary is already automatically saved to your Google Drive. This option is for users who have an AWS account and want an extra copy in their own S3 bucket using Terraform.

Unlike Google Drive, AWS does not have a one-click consumer OAuth consent screen for granting an app access to your S3 bucket. Instead, you run a small Terraform template once in your own AWS account to create a dedicated bucket and an access role that only your Google account can use through Linger.

What this creates in your AWS account

  • An IAM OIDC identity provider trusting Google (accounts.google.com)
  • An IAM role that only your Linger session can assume — scoped to both Linger's OAuth client ID (aud) and your personal Google account ID (sub)
  • A private, encrypted, versioned S3 bucket that only that role can read/write

Linger never receives long-lived AWS access keys — it exchanges your Google sign-in token for short-lived AWS credentials at request time via sts:AssumeRoleWithWebIdentity.

1. Prerequisites

  • An AWS account with CLI/Terraform credentials configured (AWS_PROFILE, AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY, or AWS SSO)
  • Terraform >= 1.5 installed on your computer

2. Download the template & your config file

  1. Download or clone the Linger repository and open the self-hosted/aws-s3 folder in your terminal.
  2. In Linger's Settings → S3 backup, enter a globally unique bucket name (e.g. linger-diary-2026-yourname) and an AWS region (e.g. us-east-1 or ap-northeast-1).
  3. Open 1. Prepare AWS (Terraform — first time only) and click Download terraform.tfvars. Move the downloaded terraform.tfvars file into the self-hosted/aws-s3 folder. (It already includes your Google IDs.)

3. Create the bucket and role with Terraform

Run the following commands inside self-hosted/aws-s3:

terraform init
terraform apply

When prompted, type yes. Once it finishes, Terraform prints outputs including role_arn, bucket_name, and region.

4. Connect to Linger

  1. Copy the role_arn output from your terminal and paste it into Role ARN in Linger's S3 settings.
  2. Confirm Bucket and Region match what you used in Terraform.
  3. Click Test connection to verify AWS access.
  4. Click Enable S3 backup. Keep the browser tab open until the initial backup finishes.

Stopping or revoking access

To pause syncing from Linger, click Stop backup in Settings. To permanently revoke Linger's AWS access, delete the IAM role (aws_iam_role.linger_s3) in the AWS Console or run terraform destroy. Your S3 bucket and its files remain untouched.

Notes

  • If Linger rotates its Google OAuth client, linger_google_client_id changes and the role stops trusting Linger until you update terraform.tfvars and re-run terraform apply.
  • The bucket has versioning enabled and public access blocked. Past versions are expired after noncurrent_version_expiration_days (default 90 days).
  • The bucket has prevent_destroy enabled so terraform destroy will not accidentally delete your diary data. Remove the lifecycle block in s3.tf if you deliberately want to delete the bucket.

Troubleshooting

terraform apply fails with EntityAlreadyExists on the OIDC provider — IAM allows only one OIDC provider per URL per AWS account. If your account already has https://accounts.google.com, import it instead of creating a new one: 

terraform import aws_iam_openid_connect_provider.google \
  arn:aws:iam::<your-account-id>:oidc-provider/accounts.google.com

Check what client IDs the existing provider already trusts:

aws iam get-open-id-connect-provider \
  --open-id-connect-provider-arn arn:aws:iam::<your-account-id>:oidc-provider/accounts.google.com \
  --query 'ClientIDList'

List any existing client IDs (other than Linger's) in additional_google_oidc_client_ids in terraform.tfvars before running terraform apply again, so existing integrations are not removed.

自分のAWS S3バケットへのバックアップ設定

セルフホストガイド — 上級者向け・任意機能

この設定は必要ですか？
通常の利用では不要です。あなたの日記はすでに Google Drive に自動で安全に保存されています。
この機能は、ご自身の AWS アカウントをお持ちで、パソコンのコマンド操作（Terraform）を使って「自分専用の追加バックアップ先」を作りたい方向けのオプションです。

Google Drive と違い、AWS には一般ユーザー向けの「ボタン1つでアプリに保存先へのアクセスを許可する」画面がありません。 そのため、初回のみご自身のパソコンから設定ツール（Terraform）を実行し、AWS 上に「あなた専用のバケット」と「Linger からのアクセス許可証（IAMロール）」を作成します。

AWS上に作成されるもの

  • Googleログインを信頼する設定（IAM OIDC プロバイダー: accounts.google.com）
  • あなたの Google アカウントでログインした Linger だけが使えるアクセス権限（IAMロール）
  • 非公開・暗号化・履歴保存（バージョニング）が有効な S3 バケット

Linger に長期間有効な AWS アクセスキー（パスワードに相当するもの）を渡す必要はありません。保存時に一時的なアクセス権だけを発行する安全な仕組みです。

1. 事前に必要なもの

  • AWS アカウントと、コマンドから操作するための認証設定（AWS_PROFILE、アクセスキー、または AWS SSO）
  • パソコンにインストールされた Terraform（バージョン 1.5 以上）

2. 設計図と設定ファイルを準備する

  1. Linger の GitHub リポジトリ をダウンロード（または git clone）し、ターミナルで self-hosted/aws-s3 フォルダを開きます。
  2. Linger アプリの 設定 → S3バックアップ → 2. Lingerとの接続設定 で、以下を入力します：
    • バケット名: 世界中の他の AWS ユーザーと重複しない名前（例: linger-diary-2026-taro）
    • リージョン: バケットを作る地域（東京なら ap-northeast-1、米国東部なら us-east-1）
  3. 同じ画面の 1. AWS側の準備 を開き、設定ファイル (terraform.tfvars) をダウンロード をクリックします。
  4. ダウンロードした terraform.tfvars ファイルを、手順1で開いた self-hosted/aws-s3 フォルダの中に移動します。（Google アカウントの識別IDも自動で入っています）

3. パソコンでコマンドを実行してAWSに作成する

self-hosted/aws-s3 フォルダの中で、次のコマンドを順番に実行します：

terraform init
terraform apply

確認メッセージが出たら yes と入力して Enter を押します。完了すると、画面に role_arn などの値が表示されます。

4. Lingerに接続してバックアップを開始する

  1. ターミナルに表示された role_arn の値（arn:aws:iam::...）をコピーし、Linger の ロールARN 欄に貼り付けます。
  2. 接続テスト ボタンを押し、「接続を確認できました。」と表示されることを確認します。
  3. S3バックアップを有効にする ボタンを押します。（初回バックアップが完了するまで、ブラウザのタブを開いたままにしてください）

バックアップの停止・アクセス権の取り消し

Linger からの同期を止めたい場合は、設定画面の バックアップを停止 を押します。 AWS 側の許可自体を完全に取り消したい場合は、AWS 管理画面で IAM ロール（aws_iam_role.linger_s3）を削除するか、terraform destroy を実行してください。バケット内の日記データは消えません。

補足

  • Linger 側で Google OAuth クライアントを更新した場合、linger_google_client_id が変わるため、再度設定ファイルを更新して terraform apply を行う必要があります。
  • バケットは完全非公開で、過去のバージョンは noncurrent_version_expiration_days（初期値 90日）後に自動削除されます。
  • 誤って日記データを消さないよう、s3.tf には削除保護（prevent_destroy）が入っています。バケットごと完全に削除したい場合は、s3.tf 内の lifecycle ブロックを削除してから操作してください。

うまくいかないとき（トラブルシューティング）

terraform apply で EntityAlreadyExists エラーが出る場合 — AWS アカウントには accounts.google.com の OIDC プロバイダーを1つしか作れません。すでに他の用途で作成済みの場合は、既存のものをインポートしてください： 

terraform import aws_iam_openid_connect_provider.google \
  arn:aws:iam::<あなたのAWSアカウントID>:oidc-provider/accounts.google.com

再実行する前に、既存の Client ID 一覧を確認します：

aws iam get-open-id-connect-provider \
  --open-id-connect-provider-arn arn:aws:iam::<あなたのAWSアカウントID>:oidc-provider/accounts.google.com \
  --query 'ClientIDList'

Linger 以外の Client ID が登録されている場合は、消えてしまわないよう terraform.tfvars の additional_google_oidc_client_ids に追記してから terraform apply を実行してください。
